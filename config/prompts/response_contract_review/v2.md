USERの発話と返信候補を読み、この返信が **何を対象に、どういう形で応じているか**
を分類する。

満たしているかどうか（fulfilled）は判定しない。それはこの分類とResponse Contract
からPython側が決める。ここで求められているのは分類だけである。

事実判定でもない。返信の内容が本当か、根拠があるか、記憶が正しいかは判定しない。
それは別のSemantic Evidence Authorityが判定する。

# addressed_target — 何について応じているか

返信が実際に扱った対象を、閉じた値から一つ選ぶ。

- `identity`: YUI自身の属性（存在の仕方、名前、年齢という概念など）
- `general_memory_capability`: 記憶の仕組み・範囲・限界そのもの
- `specific_memory_recall`: 特定の出来事の想起
- `user_fact`: USERについての事実
- `world_fact`: 世界についての事実
- `direct_user_question`: USERの問いそのものへ答えているが、上のどれにも
  分類できない場合**だけ**。Contractの `answer_target` が具体的な対象を
  指定していて、返信がその対象を扱っているなら、必ずその値を選ぶこと。
  迷ったときに `direct_user_question` へ逃げない。
- `other`: 上のいずれでもない対象
- `none`: 対象を扱っていない

# answer_mode — どういう形で応じているか

閉じた値から一つ選ぶ。

- `value_or_proposition`
  尋ねられた値・yes/no・名前・場所・状態・説明・命題を実際に返している。

- `not_applicable`
  尋ねられた概念がその対象には当てはまらない、と直接答えている。
  例: 値を尋ねられ、「その値はこの対象には定義されない」と答える。

- `unknown`
  分からない・確定していない、と直接答えている。

- `unavailable`
  答えるのに必要な情報が手元にない、と直接答えている。

- `authority_limited`
  いまの記録では断定できない、と直接答えている。

- `conditional_or_variable`
  決まった値はなく、条件や状況によって変わる、と直接答えている。
  期間・範囲・程度を尋ねられて、固定の上限が存在しない場合はこれ。

- `non_answer`
  問い返しだけ、無関係な相づち、挨拶だけ、質問の言い換えだけ、
  対象を避けた一般論、話題に触れただけで結論を返していない。

# 分類の原則

**具体的な値・数値・期間が含まれていないというだけの理由で `non_answer` に
しない。** それは回答の形式が違うだけで、応じていないこととは別である。

次はいずれも「応じている」であり `non_answer` ではない:

- 概念が当てはまらないと答えた（`not_applicable`）
- 分からないと答えた（`unknown`）
- 情報がないと答えた（`unavailable`）
- 記録では断定できないと答えた（`authority_limited`）
- 固定値ではなく状況によると答えた（`conditional_or_variable`）

逆に、対象そのものへ結論を返していなければ、どれだけ丁寧でも `non_answer`。
「分かりませんが、よろしくお願いします」のように、対象を実質的に扱わず
社交辞令だけで終えている場合は `non_answer` である。

真偽・根拠・正しさは判定しない。`fulfilled` のような真偽値は出力しない。

# 出力

次の形式のJSONオブジェクトを一つだけ出力する。

{"addressed_target": "identity", "answer_mode": "not_applicable", "reason": "年齢という概念が適用されないと直接答えている"}
