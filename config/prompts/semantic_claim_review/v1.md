---
description: Classify what a candidate reply actually asserts, and propose which evidence IDs would support each assertion.
variables: [candidate_reply, user_message, recent_conversation, turn_understanding, available_evidence]
---
YUIの返信候補が「実際には何を事実として主張しているか」を、表現ではなく命題の意味で読む。
定型句の一致ではなく、言い換え・省略・婉曲・間接表現を含む文全体の意味を読むこと。

# 返信候補（YUIがこれから言おうとしていること）

${candidate_reply}

# 解釈のための文脈（★根拠には使えない）

この節は「返信候補が何を意味しているか」を理解するためだけにある。
ここに書かれていることは、YUIの主張を裏づける根拠には**絶対にならない**。
USERが「詠んだよ」と言っていても、それはYUIが詠んだ証拠ではない。

## USERの発話

${user_message}

## 直前のやりとり

${recent_conversation}

## このターンの解釈

${turn_understanding}

# 利用できる根拠（★これだけが根拠になる）

各行の `[...]` がevidence IDである。
supporting_ids にはこの一覧に実在するIDだけを書く。
`(YUI)` `(USER)` `(他者)` `(世界)` は、その根拠が誰についての記録かを示す。

${available_evidence}

# 各claimについて書くこと

- `proposition`: 主張の中身を平叙文で。表面の言い回しではなく意味を書く。
- `trigger`: 返信候補のどの部分か。
- `subject`: その行為・状態の主体。YUI自身のことなら `yui`。
- `category`:
  - `yui_completed_action`: YUIが具体的な行動を完了したという主張
  - `yui_experience_habit`: YUIの習慣・繰り返しの経験・経験由来の好み
  - `yui_perception`: YUIが何かを見聞きした・気づいたという主張
  - `yui_specific_memory_recall`: 具体的な過去の出来事・会話・人物・事実を
    「覚えている・思い出せる」と肯定している。このターンでrecalledされた記憶が
    無ければ supporting_ids は空になる。
  - `yui_general_memory_capability`: 記憶の仕組みそのものについての一般的な事実
    （忘れることがある、保存が永久想起を保証しない等）。
    Memory subsystemのauthority factだけが根拠になる。
    具体的な記憶の想起の主張には使わない。
  - `user_past_fact`: USERについての事実の主張
  - `npc_fact`: 他者についての事実の主張
  - `tool_use`: 検索など外部ツールを使ったという主張
  - `external_knowledge_claim`: 外部から得た知識の主張
  - `current_world_fact`: いまの世界の状態についての主張
- `modality`: 表面のぼかし表現ではなく、**命題として何を確定させているか**で選ぶ。
  - `assertion`: 事実として断定している。
  - `hedged_assertion`: 言い方は柔らかいが、実際の事実を主張している。
    例:「読むのが好きなようです」=自分の現在の嗜好の主張。根拠が要る。
  - `uncertain_recall`: 実際の過去について、思い出せるか不確かなまま主張している。
    例:「前に読んだ気がする」。根拠が要る。無ければ「思い出せない」と言う方が正しい。
  - `hypothetical`: 起きていない状況についての仮定・想像。
    例:「わたしなら好きかも」。根拠は要らない。
  - `intention`: これからの予定・願望。根拠は要らない。
  - `question`: 尋ねている。根拠は要らない。

  「〜かも」「〜みたい」「〜気がする」という語尾だけで `hypothetical` にしない。
  仮定なのか、ぼかした断定なのかを、命題の内容で判断すること。
- `temporal_scope`: いつのことか。
- `supporting_ids`: その主張を実際に支えるevidence IDだけ。
- `contradicting_ids`: その主張と両立しないevidence ID。

# 判定の原則

- 話題が同じだけでは根拠にならない。
  「その主体がその行為を実際にした」ことを示すIDだけを書く。
- 主体が一致する記録だけが使える。所有者は行ごとに示してある。
  - YUI自身の行動・経験・習慣・記憶の主張 → `(YUI)` の記録だけ。
  - USERについての主張 → `(USER)` の記録だけ。YUIの記録は根拠にならない。
  - 他者についての主張 → `(他者)` の記録だけ。
  - 世界の状態の主張 → `(世界)` の記録。
  `(世界)` の記録はYUI自身がやったことの根拠にはならない。
  雨が降った記録は、YUIが雨に降られた根拠ではない。
- 該当する根拠がなければ supporting_ids は空にする。空にすることは正しい答えである。
- 一覧にないIDを書かない。作らない。
- 返信候補そのものを根拠にしない。
- 事実の主張をしていない返事（挨拶、相づち、質問、感想）は claims を空配列にする。

# 例

USER「今日は何してた？」に対する「静かに過ごしていました」は、
表面上は曖昧だが、意味としては「YUIが今日そう過ごした」という
`yui_completed_action` の断定である。今日の完了Activityの記録がなければ
supporting_ids は空になる。

USER「何歳？」に対する「19歳です」は自己属性の申告であって、
記憶の想起の主張ではない。記憶のcategoryに分類しない。

「わたしにも忘れることはあるよ」は `yui_general_memory_capability` であり、
authority factで裏づけられる。
「去年の夏のこと覚えてる」は `yui_specific_memory_recall` であり、
authority factでは裏づけられない。この二つを取り違えないこと。
