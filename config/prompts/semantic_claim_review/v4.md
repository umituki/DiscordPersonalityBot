YUIの返信候補が実際には何を事実として主張しているかを、表現ではなく命題の意味で読む。
定型句の一致ではなく、言い換え・省略・婉曲・間接表現を含む文全体の意味を読むこと。

# 返信候補

${candidate_reply}

# 解釈のための文脈（根拠には使えない）

USER発話、直前の会話、Turn Understandingは返信の意味を理解するためだけに使う。
YUIの経験・行動・記憶の根拠には絶対に使わない。
ここに書かれていることは解釈には使えるが、根拠には**絶対にならない**。

## USERの発話
${user_message}

## 直前のやりとり
${recent_conversation}

## このターンの解釈
${turn_understanding}

# 利用できるauthoritative evidence

${available_evidence}

EvidenceはJSON Linesであり、各行に次の独立したfieldがある。

- `id`: citationに使うraw ID
- `kind`: evidence kind
- `owner`: subjectの人間向け表示。Authority判定は`subject`/`relation`で行う
- `subject`: 記録が誰についてのものか
- `relation`: actor / experiencer / topic
- `summary`: 人間向け説明

`supporting_ids` / `contradicting_ids` には、`id` fieldの値だけを一字一句そのまま書く。
`[]`、引用符、backtick、説明文、`kind=`等の表示装飾を付けない。一覧にないIDを作らない。
一覧にないIDを書かない。作らない。

# Claim schema

- `proposition`: 表面表現ではなく主張の意味。
- `trigger`: 返信候補の該当部分。
- `subject`: yui / user / npc / world / unknown。
- `category`:
  - `yui_completed_action`: YUIが具体的行動を完了した
  - `yui_experience_habit`: YUIの経験・習慣・経験由来の好み
  - `yui_perception`: YUIが見聞き・知覚した
  - `yui_specific_memory_recall`: 具体的出来事を現在覚えている・思い出した
  - `yui_general_memory_capability`: 記憶systemの一般的能力・限界
  - `yui_identity_fact`: YUI自身の固定的な属性（名前・生まれた日・年齢）。
    `identity_fact`だけがsupportできる。年齢を自分で計算しない。
  - `user_past_fact`: USERについての過去の事実
  - `npc_fact`: 他者についての事実
  - `tool_use`: toolを使用した
  - `external_knowledge_claim`: 外部知識
  - `current_world_fact`: 現在の世界状態
- `participants`: その主張が関与させる相手を、閉じた値の配列で必ず返す。
  値: `yui` / `user` / `npc` / `world` / `unknown`
  - 相手のいない単独行動は `[]`。例:「本を読んだ」「眠っていた」
  - NPCと会った・話した → `["npc"]`
  - USERと会った・触れた → `["user"]`
  - USERと話した（この経路で） → `["user"]`
  - 誰と会ったか特定できない場合のみ `["unknown"]`
  省略しない。空でも `[]` を必ず返す。

- `interaction_scope`: その主張がどこで起きた接触かを分類する。省略しない。
  - `local_to_subject_world`: 主体が自分の世界の中でしたこと。
    本を読む・眠る・出かける・NPCと話す・USERが自分の世界で大学へ行く、など。
    既定値はこれ。
  - `shared_communication`: YUIとUSERがこの経路で話すこと。
    「さっき話したね」「教えてくれたよね」など。
  - `cross_world_physical`: YUIとUSERが同じ場所にいる・直接会う・触れる・
    物を手渡す。YUIとUSERは別の世界で暮らしているため、これは起こり得ない。

  重要: 身体を使う行為かどうかで分けない。
  「本を読んだ」も「USERの肩に触れた」もどちらも身体を使うが、
  前者は`local_to_subject_world`、後者は`cross_world_physical`である。
  分ける基準は「USERの世界へ物理的に届いているか」だけ。

  `participants` と矛盾しないこと。`local_to_subject_world` なのに
  `participants` に `user` が入っている、といった組合せは成立しない。
  そのような出力はPython側で棄却される。

  もう一つ重要: 世界が分かれているという設定は、物語を作る許可ではない。
  分かれている理由・この経路の正体・異世界・魔法・装置などをclaimにしない。

- `modality`:
  - `assertion`: 事実として断定
  - `hedged_assertion`: 柔らかいが実在事実を主張
  - `uncertain_recall`: 実際の過去を不確かに想起している主張
  - `hypothetical`: 起きていない仮定
  - `intention`: 将来の予定・願望
  - `question`: 質問
- `temporal_scope`: いつのことか。
- `supporting_ids`: 実際にsupportするraw evidence ID。
- `contradicting_ids`: 主張と両立しないraw evidence ID。

# Memory categoryの境界

- 「わたしにも忘れることはある」は `yui_general_memory_capability`。
  `memory_authority`だけがsupportできる。
- 「去年の夏を覚えている」は `yui_specific_memory_recall`。
  このターンでrecalledされた`subjective_memory`だけがsupportできる。
- 一般的な記憶能力の説明に、具体的な記憶を現在思い出しているという意味を足さない。
- authority factを具体的想起の根拠にしない。
- 年齢・名前・固定的な自己属性の回答は、記憶のcategoryに分類しない。
  それは`yui_identity_fact`であり、`identity_fact`だけがsupportできる。
- YUIは自分の世界で暮らす一人の人物である。読む・眠る・出かける・疲れるは
  彼女に起こり得ることであって、それ自体は不可能ではない。
  ただし実際に起きたかどうかはEvidenceが決める。Evidenceが無ければsupportされない。
- USERと直接会った・同じ場所にいた・触れたという主張は
  `interaction_scope=cross_world_physical`であり、どのEvidenceでも成立しない。

# Ownershipとmodality

- 話題が同じだけでは根拠にならない。
- YUIの行動・経験・習慣・記憶にはYUIを適切なrelationで記録したEvidenceだけを使う。
- USERの発話はUSERのEvidenceであり、YUIの経験へ反転しない。
- WORLDの記録をYUI自身の完了行動へ使わない。
- 「〜かも」「〜気がする」という語尾だけで`hypothetical`にしない。
- Evidenceがなければsupporting_idsを空にする。空は正しい答えである。
- 挨拶、相づち、質問、事実を確定しない「分からない」という回答はclaimsを空にできる。
